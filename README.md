# WordTrainer — тренажёр для изучения иностранных слов

Веб-приложение на Django для запоминания иностранных слов: свой словарь, тематические группы, примеры предложений и упражнения с подсчётом статистики по каждому слову.

## Возможности

- **Слова**: добавление, редактирование и удаление слов с переводом, транскрипцией и частью речи
- **Группы**: объединение слов в тематические наборы
- **Предложения**: примеры употребления, привязанные к словам
- **Синонимы**: связи между словами внутри словаря
- **Упражнения** трёх типов:
  1. выбор правильного перевода из вариантов
  2. написание слова по переводу
  3. просмотр предложений с изучаемыми словами
- **Статистика**: счётчики верных и неверных ответов по каждому слову, история попыток
- **Поиск** по словам, переводам, группам и предложениям
- **Импорт/экспорт**: импорт слов из CSV, экспорт в CSV и HTML

Интерфейс — одностраничный, с вкладками; переходы выполняются AJAX-запросами к `/ajax/...`.

## Быстрый старт в Docker

Требуется только Docker Desktop.

```bash
docker compose up -d --build
```

Приложение будет доступно на **http://localhost:8000**.

Логин и пароль по умолчанию: **`admin` / `admin`**.

При старте контейнера `web` скрипт `djproject/docker_start.py` автоматически:

1. ждёт готовности PostgreSQL;
2. создаёт таблицы (`syncdb` — в Django 1.4 ещё нет `migrate`);
3. загружает начальные данные (части речи и типы упражнений) из `djproject/core/fixtures/initial_data.json`;
4. создаёт суперпользователя, если его ещё нет;
5. запускает Gunicorn.

Повторный запуск безопасен: существующие таблицы и пользователь не пересоздаются.

### Как устроены сервисы

- **nginx** — принимает запросы на порту 8000, сам отдаёт статику из `/media/` и проксирует остальное в Django
- **web** — Gunicorn с тремя воркерами
- **db** — PostgreSQL, данные хранятся в томе `postgres_data`

Код копируется в образ, а не монтируется с хоста (bind-mount на Windows заметно замедляет работу). **После изменения кода нужна пересборка:**

```bash
docker compose up -d --build
```

### Полезные команды

```bash
docker compose logs -f web          # логи приложения
docker compose ps                   # статус сервисов
docker compose down                 # остановить
docker compose down -v              # остановить и удалить данные БД
docker compose exec -w /app/djproject web python manage.py syncdb
```

Админка Django — http://localhost:8000/admin/

## Переменные окружения

Для Docker все значения заданы в `docker-compose.yml`. Файл `djproject/.env` **не читается автоматически** — `djproject/core/env.py` берёт значения только из окружения процесса.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | да | подключение к PostgreSQL |
| `DB_HOST`, `DB_PORT` | нет | по умолчанию `localhost` и `5432` |
| `SECRET_KEY` | да | ключ Django |
| `ADMIN_EMAIL` | да | адрес администратора |
| `EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `SERVER_EMAIL` | да | параметры SMTP |
| `DEBUG` | нет | `True` включает режим отладки |
| `EMAIL_BACKEND` | нет | в Docker — консольный backend, чтобы SMTP не блокировал запросы |
| `GUNICORN_WORKERS` | нет | число воркеров, по умолчанию 3 |
| `USE_TEMPLATE_CACHE` | нет | `1` включает кеширующий загрузчик шаблонов |
| `DJANGO_ADMIN_USER`, `DJANGO_ADMIN_PASSWORD` | нет | логин и пароль создаваемого суперпользователя |
| `MEDIA_ROOT` | нет | путь к статике, по умолчанию `htdocs/media` |

Перед публикацией в интернет обязательно замените `SECRET_KEY`, пароли БД и почты, а `DEBUG` выставьте в `False`.

## Структура проекта

```
djproject/              Django-проект (settings и urls — модули верхнего уровня)
  settings.py           настройки
  urls.py               корневые маршруты, включая /admin/
  manage.py             CLI Django
  wsgi.py               точка входа для Gunicorn
  docker_start.py       инициализация БД и запуск сервера в контейнере
  core/
    models.py           Word, Group, Sentence, Exercise, Record, SpeechPart, Config
    entities.py         CRUD для всех сущностей
    exercises.py        логика упражнений и подсчёт результатов
    config.py           настройки пользователя, импорт и экспорт
    search.py           поиск по словарю
    auth.py             вход и выход
    decorators.py       auth_required, обёртки для обработки ошибок
    forms.py            формы сущностей и экспорта
    urls.py             AJAX-маршруты
    templates/          HTML-шаблоны
    fixtures/           начальные данные
htdocs/media/           статика: CSS, JS, изображения (отдаёт nginx)
Dockerfile              образ приложения
docker/                 образ и конфигурация nginx
backup/                 пример CSV для импорта
```

Обратите внимание: статика лежит по адресу `/media/`, а не `/static/` — так исторически настроен `STATIC_URL`.

## Модель данных

- `Word` — слово: написание, перевод, транскрипция, часть речи, счётчики `success` и `failed`, флаг участия в упражнениях
- `Group` — тематическая группа слов
- `Sentence` — предложение с переводом
- `SpeechPart` — часть речи (существительное, глагол и т. д.)
- `ExerciseType` — тип упражнения
- `Exercise` — упражнение с фильтрами по группе, части речи, дате создания слов и числу ошибок
- `Record` — результат одной попытки: слово, упражнение, признак успеха
- `Config` — настройки пользователя, например число элементов на странице

Все сущности, кроме справочников, привязаны к пользователю.

## Использование

1. Войдите в систему.
2. Добавьте слова: написание, перевод, при необходимости транскрипцию, и обязательно часть речи.
3. Сгруппируйте слова по темам и при желании добавьте синонимы и примеры предложений.
4. Создайте упражнение, выбрав тип и фильтры (группа, часть речи, диапазон дат, минимальное число ошибок).
5. Пройдите упражнение — результат каждой попытки сохраняется в статистике слова.
6. При необходимости экспортируйте словарь в CSV или HTML.

Горячие клавиши: `Ctrl + клик` — открыть в новой вкладке, `Alt + W` — закрыть вкладку, `Alt + A` — закрыть все вкладки, `Alt + R` — обновить высоту вкладки.

## Запуск без Docker

Нужны Python 2.7 и PostgreSQL. Зависимости — в `requirements.txt`.

```bash
pip install -r requirements.txt
cd djproject
python manage.py syncdb
python manage.py loaddata core/fixtures/initial_data.json
python manage.py createsuperuser
python manage.py runserver
```

Переменные окружения из таблицы выше должны быть выставлены в оболочке — иначе `settings.py` завершится с `ImproperlyConfigured`.

`runserver` в Django 1.4 однопоточный и сам отдаёт статику, поэтому подходит только для локальной разработки.
